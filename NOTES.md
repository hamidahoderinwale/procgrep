# NOTES

Running engineering notes: decisions and the why behind them, newest on top,
plain English. Per-file Intent and design decisions live in the module
docstrings; this file captures cross-cutting choices.

## Interactive figures share one D3 module (2026-06)
The web essay's figures (scaffold-vs-model JSD dot plot, follow-through,
representation-F1 bars, distillation entropy box plot) render through one
module, `docs/explorer/d3charts.js` (`logDotPlot` / `barChart` / `boxPlot`),
reusing the editorial palette. Why: one chart implementation shared by the
explorer and the essay, so hover-for-values and a value-label toggle come for
free and the static-figure palette is preserved. Each figure ships as data
(`docs/paper/data/*.json`) plus a standalone HTML, generated by `scripts/fig_*.py`.
The LaTeX paper keeps the static PNGs.

## Spine store schema (2026-06)
Each row of `data/procgrep_spines.parquet` is one trajectory: `dataset`,
`trace_id`, `agent`, `task`, `spine`, `outcome`, `cot_tokens`. The explorer
prefers the store and falls back to live ingest. `cot_tokens` is a per-trace
reasoning-token estimate (sum of `chars/4` over model-role turns), used for the
reasoning-volume readouts in the query stats line and comparator.
